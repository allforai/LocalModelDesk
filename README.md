# 本地模型台

一台 Mac 上既要本地聊天，又要出视频、出歌。这几类模型都很大，统一内存里装不下两份。这个项目要解决的是：把它们收成一张日常能用的工作台，并且保证同一时刻只有一件重活占着机器。

不上云。不为多人排队。不是通用模型市场。

## 问题

本机已经有聊天、视频、音乐三类能力，但它们各自是命令行、各自会打满内存。当日常工具用会碰到：

- 想聊时要先想起加载哪个模型；想出片时又要自己腾内存
- 70B 级对话和视频/音乐生成不能同时驻留，忘了卸就会抢崩
- 模型体积以百 GB 计，下没下齐、下到一半，没有一张清单
- 生成结果散落各处，提示词和参数回不去，做不成迭代

需要的是一张台：坐下就能聊、能出片、能出歌；切换时不用自己记该停谁。

## 谁用

一个人、一台大内存 Mac、模型都放本机。推理不出门，成品不出门。

## 必须能做到

### 本机对话

- 从已下载的聊天模型里选一个加载，然后对话
- 回复要边生成边看；模型的思考过程看得到
- 关掉再开，最近的对话还在
- 有视觉能力的模型要标出来；会打满内存的模型要在加载前警告

### 文生视频

- 用一段提示词生成带环境声的短视频
- 能在草稿和更清晰之间选画幅，能调长短与品质
- 生成过程看得到进度；完成后能直接播

### 文生歌曲

- 用风格描述、歌词和时长生成一首歌
- 完成后能直接听

### 同一时刻只干一件重活

- 聊天模型、视频生成、音乐生成不能同时驻留
- 出视频或出歌前，自动让出内存
- 出片期间不能再加载聊天模型，也不能开下一个生成任务
- 台面上随时能看出：内存里是谁、媒体是否在跑、现在能不能开下一件

### 模型齐不齐一眼能看出来

- 聊天、视频、音乐模型都允许分次下载，中断后续传
- 能列出目录，看每一项是齐了、下了一半、还是没有
- 权重不进代码仓库；换机器用同一套步骤把模型补回来

### 成品不丢、能再做一版

- 视频和音频留在本机
- 能从历史里点开旧成品，并把当时的提示词和参数填回去

### 随时在

- 开机后工作台是活的；打开就能用，不必先想起一串命令

## 明确不做

- 不把请求发到云端，也不给多人共用
- 不收录任意模型，只服务这张台上选定的聊天、视频、音乐能力
- 不追求 70B 对话和视频生成同时驻留
