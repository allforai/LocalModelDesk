# 本地模型台

一台 Mac 上既要本地聊天，又要出视频、出歌。这几类模型都很大，统一内存里装不下两份。这个项目要解决的是：把它们收成一张日常能用的工作台，并且保证同一时刻只有一件重活占着机器。

不上云。不为多人排队。不是通用模型市场。

## 问题

本机已经有聊天、视频、音乐三类能力，但它们各自是命令行、各自会打满内存。当日常工具用会碰到：

- 想聊时要先想起加载哪个模型；想出片时又要自己腾内存
- 70B 级对话和视频/音乐生成不能同时驻留，忘了卸就会抢崩
- 模型体积以百 GB 计，下没下齐、下到一半，没有一张清单
- 生成结果散落各处，提示词和参数回不去，做不成迭代

需要的是一张台：坐下就能聊、能出片、能出歌；切换时不用自己记该停谁。

## 谁用

一个人、一台大内存 Mac、模型都放本机。推理不出门，成品不出门。

## 必须能做到

### 本机对话

- 从已下载的聊天模型里选一个加载，然后对话
- 回复要边生成边看；模型的思考过程看得到
- 关掉再开，最近的对话还在
- 有视觉能力的模型要标出来；会打满内存的模型要在加载前警告

### 文生视频

- 用一段提示词生成带环境声的短视频
- 能在草稿和更清晰之间选画幅，能调长短与品质
- 生成过程看得到进度；完成后能直接播

### 文生歌曲

- 用风格描述、歌词和时长生成一首歌
- 完成后能直接听

### 同一时刻只干一件重活

- 聊天模型、视频生成、音乐生成不能同时驻留
- 出视频或出歌前，自动让出内存
- 出片期间不能再加载聊天模型，也不能开下一个生成任务
- 台面上随时能看出：内存里是谁、媒体是否在跑、现在能不能开下一件

### 模型齐不齐一眼能看出来

- 聊天、视频、音乐模型都允许分次下载，中断后续传
- 能列出目录，看每一项是齐了、下了一半、还是没有
- 权重不进代码仓库；换机器用同一套步骤把模型补回来

### 成品不丢、能再做一版

- 视频和音频留在本机
- 能从历史里点开旧成品，并把当时的提示词和参数填回去

### 安装与卸载

```bash
# 安装（目标目录必须已存在；默认装到 /Applications）
./scripts/install-app.sh --app dist/LocalModelDesk.app

# 卸载（先看要删什么，再真删；模型目录永远保留）
./scripts/uninstall-app.sh --dry-run
./scripts/uninstall-app.sh
```

`--help` 可列出全部参数。卸载默认保留 `~/Library/Application Support/LocalModelDesk` 下的数据；加 `--purge-data` 才会清除（模型目录仍保留）。

### 分发给其他机器（需要 Apple 开发者账号）

一次性准备：

```bash
xcrun notarytool store-credentials LocalModelDesk \
  --apple-id <你的 Apple ID> --team-id <Team ID> --password <App 专用密码>
```

之后出包时带上 `LMD_NOTARY_PROFILE=LocalModelDesk ./scripts/build-app.sh`，脚本会自动提交公证并 staple。不设该变量时只做 Developer ID 签名，本机可用、别的机器会被 Gatekeeper 拦。

### 安装后的实际行为

- 安装后不会自动启动；从“应用程序”打开本地模型台后，服务才会随应用启动。关闭窗口不会退出，使用菜单栏图标或“退出本地模型台”才会停止它。
- 首次打开时选择模型目录；默认目录是 `~/Library/Application Support/LocalModelDesk/models`。已有模型可收编已有模型目录：可以直接指向原目录，或把已识别的模型移入新目录，无须重新下载。
- 默认网关监听 `0.0.0.0:8770`，同一局域网的设备可访问。本服务无鉴权；请只在可信网络中启用，或在设置中关闭网关。

### 构建与签名

- `scripts/build-app.sh` 默认要求 Developer ID Application 证书；用 `security find-identity -v -p codesigning` 查看本机可用身份，再用 `--identity "Developer ID Application: ..."` 传给构建脚本。
- 默认输出 `dist/LocalModelDesk.app`；`--output <目录>` 可放到任意位置（仓库内外都行，包内不会留下构建机路径）。
- 仅本机调试可用 adhoc 签名：设置环境变量 `LMD_ALLOW_ADHOC=1` 并传 `--adhoc`；adhoc 签名的应用在其他机器上会被 Gatekeeper 拒绝打开，因此构建脚本在缺少该环境变量时拒绝静默降级为 adhoc。
- `scripts/verify-app.sh` 会额外用 `spctl --assess --type execute` 校验 Gatekeeper 是否接受该包；未设置 `LMD_ALLOW_ADHOC=1` 时若被拒绝，验证失败。

## 明确不做

- 不把请求发到云端，也不给多人共用
- 不收录任意模型，只服务这张台上选定的聊天、视频、音乐能力
- 不追求 70B 对话和视频生成同时驻留
