# 模块设计：ui

**日期** 2026-08-31
**spec** `docs/superpowers/specs/2026-08-31-ui-spec.md`
**覆盖需求** R-ui-01 … R-ui-10
**消费（数据形状补充声明，Phase 1.2 对齐）** 除 spec 消费清单外，本模块作为所消费 api 的载荷
渲染方，还消费以下注册表数据形状：`data:llmState`（`api:llmStatus` 载荷，聊天面板状态）、
`data:jobState`（`api:jobStatus` 载荷，视频/音乐面板）、`data:chatSession`（会话列表与回放）、
`data:gatewayStatus`（`api:gatewayConfig` GET 载荷，settings 面板）、`data:memorySnapshot`
（`api:memorySnapshot` 载荷，状态条）。词汇均取自注册表，未新增接口。

## 1. 架构

### 1.1 总体形态

ui 模块 = **一小片服务端静态供给代码** + **一整套静态前端**。

```
desk/ui.py                     # 服务端：静态文件供给（本模块唯一的 Python 面）
desk/static/                   # 前端全部静态资源（无构建链，零 node_modules）
  index.html                   # 唯一页面：ui:deskShell
  app.css                      # 全部样式
  js/
    main.js                    # 启动引导、面板切换、轮询循环
    api.js                     # 台面 HTTP 端点的唯一映射点（registry api:* → URL）
    store.js                   # 极轻量状态容器 + 订阅
    stream.js                  # fetch ReadableStream → SSE 行的读取壳（薄，DOM 无关）
    panes/
      chat.js                  # ui:chatPane
      video.js                 # ui:videoPane
      music.js                 # ui:musicPane
      resources.js             # ui:resourcesPane
      library.js               # ui:libraryPane
      firstrun.js              # ui:firstRunPane
      settings.js              # ui:settingsPane
    widgets/
      statusbar.js             # ui:statusBar
      confirm.js               # 通用确认弹层（内存警告 / 删除确认共用）
    pure/                      # 纯逻辑 ES 模块：零 DOM、零 fetch、零计时器
      chat_stream.js           # SSE data 行 → {content, reasoning} 增量归并
      model_status.js          # data:modelStatus → 徽标文案/百分比/控件可用性
      desk_state.js            # data:deskState + data:memorySnapshot → 状态条视图数据
      mem_warn.js              # (模型字节数, 内存快照) → 是否需要加载前警告
      history_fill.js          # data:historyEntry.params → 目标面板 + 表单字段映射
      base_url.js              # gateway 配置 → OpenAI / Anthropic 两条 base URL
      sessions.js              # 会话列表排序、默认标题推导
      format.js                # 字节 / 百分比 / 时长 / 时间戳格式化
tests/
  test_ui_static.py            # pytest：静态供给 + 「Python 内无内联 HTML」断言
  js/
    *.test.js                  # node --test：pure/ 下每个模块一份
```

### 1.2 关键原则

1. **薄 DOM、厚纯函数**。所有能脱离浏览器验证的逻辑（流解析、状态映射、回填映射、
   格式化、警告判定）都在 `js/pure/` 里，`node --test` 直接 import 跑。
   panes/ 与 widgets/ 只做「取数 → 调纯函数 → 写 DOM」。
2. **api.js 是端点的唯一映射点**。前端任何地方不得手写 URL 字符串；
   registry 的每个被消费 `api:*` 在 api.js 里恰有一个函数。sibling 模块的路由若与
   本设计的暂定路径不一致，改动收敛在这一个文件（见 §7 Assumptions）。
3. **绝不直连 mlx-lm**。前端代码中不得出现 `8767`；聊天只走 `api:chatStream`
   （消灭 census A17，让 A18 的代理成为唯一通路）。
4. **错误就是错误**。服务端返回的错误原样展示在发生处（面板内联或状态条），
   不吞、不改写成温和的成功、不自动重试掩盖。
5. **轮询为主，流式仅用于聊天**。台面状态、作业进度、下载进度都用短轮询
   （现行 `tick()` 模式的整理版）；不引入 WebSocket / EventSource 基建。
   registry 的 `event:*` 由服务端模块内部使用，ui 不消费（spec 消费清单里也没有它们）。

### 1.3 服务端静态供给（desk/ui.py）

- `StaticAssets(static_root: Path)`：构造时收静态根目录——**根目录来自
  `api:resolvePaths`（bundle 资源根下的 `desk/static/`），本模块不拼任何路径**。
- 接口（供服务端组装层挂载）：
  - `resolve(url_path: str) -> tuple[Path, str] | None`：把 `/`、`/index.html`、
    `/static/js/...` 映射为 (文件路径, Content-Type)；路径先 `resolve()` 再校验落在
    static_root 之内，逃逸返回 `None`（404）。
  - Content-Type 表：`.html → text/html; charset=utf-8`、`.css → text/css; charset=utf-8`、
    `.js → text/javascript; charset=utf-8`。表外后缀不供给（404）——static 目录里只应有这三类。
- 不缓存、不压缩、不做 ETag（本机 loopback 供给，YAGNI）。

## 2. 组件

### 2.1 ui:deskShell（index.html + main.js + app.css）

- 单页面。结构：顶部 `ui:statusBar`（常驻）→ 五个 tab（聊天 / 视频 / 音乐 / 资源 / 素材库）
  + 右上角「设置」入口 → 主区域按 tab 显示对应 pane 的 DOM 子树（`hidden` 切换，不销毁）。
- 启动序列（main.js）：
  1. `api.readConfig()`；
  2. needs-setup（无配置或 `first_run_done` 为假）→ 全屏显示 `ui:firstRunPane`，
     其余不初始化；
  3. 否则初始化各 pane、启动轮询循环。
- 轮询循环（单一定时器，2s）：每拍取 `data:deskState` + `api:memorySnapshot` 喂状态条；
  有媒体作业在跑时加取 `api:jobStatus`；资源面板可见且有下载在跑时加取下载进度。
  请求失败一次不清空界面，连续失败 ≥3 次在状态条显示「服务失联」。
- 深色主题延续现行视觉（`color-scheme: dark`，单一主题即可，App 内嵌 WebView 无系统切换诉求）。
- DOM 写入一律 `createElement` / `textContent`；不把任何用户或模型产生的字符串塞进
  `innerHTML`（现行代码的 `escapeHtml`+innerHTML 模式废弃）。

### 2.2 ui:statusBar（widgets/statusbar.js + pure/desk_state.js）【R-ui-07】

- 输入：`data:deskState`（持有者、媒体是否在跑、能否开下一件、不能的原因）
  + `data:memorySnapshot`（总量/已用/可用/压力，均来自真实读数）。
- `desk_state.js` 纯函数 `renderState(deskState, memSnapshot) -> {memText, holderText, mediaText, nextText, tone}`：
  - 内存显示 `已用 X.X / 总 Y GB（可用 Z GB）`，由快照字节数格式化，**不存在任何常量 128**；
  - `holderText`：`空闲` / `LLM：<名称>` / `视频生成中` / `音乐生成中`；
  - `nextText`：`可开下一件重活` 或 `不可：<机器可读原因的中文文案>`；
  - `tone`: `ok | busy | error`，决定状态条配色。
- widgets/statusbar.js 只做 DOM 更新。

### 2.3 ui:chatPane（panes/chat.js + pure/chat_stream.js + pure/sessions.js）【R-ui-02, R-ui-08】

布局：左列会话列表，右列 模型区 + 消息流 + 输入框。

**模型区**
- 下拉列出 `api:listCatalog` 中 `group == "chat"` 的项，标注 名称 / GB / 量化 / 参数量 /
  视觉徽标（B05）；`data:modelStatus` 非 `present` 的项禁用并标注「未下载/不完整」。
- 「加载」流程（R-ui-08）：
  1. 取所选 `data:modelEntry` 的体积与最新 `api:memorySnapshot`；
  2. `mem_warn.js` 纯函数 `needsWarning(modelBytes, snapshot) -> {warn, message}`——
     判定规则：模型字节数 ≥ 快照可用字节数即警告，message 含双方数字；
  3. `warn` 为真 → `confirm.js` 弹层，用户确认才继续，取消即中止；
  4. `api.loadLlm(key)`；加载中轮询 `api:llmStatus` 展示 `loading`，失败展示服务端原因
     （含 mlx-lm 日志尾部，R-llm-04 提供）。
- 「卸载」→ `api.unloadLlm()`。
- 当前加载模型（`api:llmStatus` 的 `data:loadedModel`）在模型区高亮显示。

**会话列表**
- `api:listChatSessions` 列出（`sessions.js` 按更新时间倒序；无标题的以首条用户消息
  截断 24 字作为显示标题）；操作：新建（`api:createChatSession`）、切换（读该会话消息渲染）、
  重命名（行内编辑 → `api:updateChatSession`）、删除（confirm.js 确认 → `api:deleteChatSession`）。
- 当前会话 id 存在 store 里；启动时选最近更新的会话，没有则新建。

**流式对话**
- 发送：把用户消息 append 进当前会话的消息数组 → `api.chatStream(messages)`
  （fetch + ReadableStream，stream.js 切行）→ 每个 `data:` 行交
  `chat_stream.js` 的 `reduceChunk(state, line)`：
  - 输入一行 SSE data，输出新的 `{content, reasoning, done, error}`；
  - 正文增量与思考增量（服务端已按 R-llm-03 分字段传）分别累加，**不混流**；
  - `[DONE]` 置 done；`{"error":...}` 行置 error；解析失败的行忽略但不中断。
- 渲染：思考过程放 `<details>`（生成中默认展开、有正文后折叠，延续现行交互）；
  正文随增量刷新。
- 流结束后：把 assistant 消息（含 reasoning）写回会话 → `api.updateChatSession(id, {messages, model})`。
- 被拒（媒体在跑 / 无模型，R-llm-06 的 4xx/503）：在消息流位置内联展示服务端原因，
  不留空转圈。

### 2.4 ui:videoPane（panes/video.js）【R-ui-03】

- 表单：提示词（textarea）、画幅（预设下拉 512×288 / 768×448 / 1024×576，值即 `宽x高`）、
  帧数、步数（number，min/max 沿用现行）。
- 「生成」→ `api.startVideoJob({prompt, width, height, frames, steps})`；
  被拒（arbiter 占用）→ 按钮下内联展示机器可读原因的文案。
- 进行中：轮询 `api:jobStatus` 渲染 状态 + 滚动日志（`<pre>` 尾随滚动）+「取消」按钮
  （`api.cancelJob()`）。
- `data:jobState` 转 done 且有产出 → 就地 `<video controls>`，src 为
  `api.outputUrl(name)`（`api:serveOutput` 的 URL，支持 Range 拖动由 library 模块保证）。
- 失败 → 展示状态与原因，日志保留。

### 2.5 ui:musicPane（panes/music.js）【R-ui-04】

与 videoPane 同构，仅表单不同：风格描述、歌词（textarea）、时长（秒）。
产出用 `<audio controls>`。二者共用一个「作业渲染」内部辅助（进度/日志/取消/播放器），
因为 `data:jobState` 是同一形状。

### 2.6 ui:resourcesPane（panes/resources.js + pure/model_status.js）【R-ui-05】

- 进入面板时 `api:listCatalog` + `api:verifyAllModels` + `api:diskUsage` 各取一次；
  顶部显示：models 根路径、已占盘合计、**所在卷剩余空间**。
- 每个目录项一行，`model_status.js` 纯函数
  `rowView(entry, status) -> {badge, pct, sizeText, diskText, actions, missing}`：
  - 徽标：`present → 齐`；`partial → 一半 N%`（N 为字节百分比，来自 `data:modelStatus`）；
    `missing → 没下`；
  - 显示声明体积与实际占盘字节（format.js）；
  - `actions` 按状态给出可用控件集合：
    `missing → [下载]`；`partial → [续传, 删除]`；`present → [删除]`；
    下载中 → `[取消]` + 进度条。
- `partial` 行可展开，列出缺失/短缺文件清单（`data:modelStatus` 携带）。
- 下载与续传：二者同走 `api.startDownload(key)`（registry 无独立续传接口；对 `partial`
  目录由 resources 模块的字节级续传语义决定从断点继续，ui 不区分也不清理）；
  进行中轮询 `data:downloadProgress`
  （已完成/总字节、当前文件、速率、预估剩余，直接格式化展示）；
  「取消」→ `api.cancelDownload()`（resources 合同：单飞下载，无 key 参数；服务端保证已下部分可续传，ui 不做任何清理动作）。
  同时只有一个下载（R-resources-09），其余项的下载按钮在有下载进行时禁用并注明原因。
- 删除：confirm.js 弹层展示 项名 + 将回收的字节数，确认后
  `api.deleteModel(key, {confirm: key})`（resources 合同：确认参数必须**等于目标 key**，布尔值会被拒；ui 永远带上）；
  完成后重取 verify + diskUsage 刷新。
- 下载被拒（重活在跑）→ 内联展示服务端原因。

### 2.7 ui:libraryPane（panes/library.js + pure/history_fill.js）【R-ui-06】

- 进入面板取 `api:listOutputs` + `api:listHistory` 合并渲染为一个时间倒序列表：
  历史条目显示 提示词摘要 / 类别 / 时间 / 耗时 / 规格，孤儿成品（磁盘有、历史无）
  显示文件名并标注「无历史记录」。
- 点条目：有产出文件 → 面板内播放器就地播放（`api.outputUrl(name)`）。
- 「回填」按钮（仅有 params 的历史条目显示）：
  `history_fill.js` 纯函数 `fillPlan(historyEntry) -> {pane: 'video'|'music', fields: {...}} | null`
  —— `kind` 为视频 → `{prompt, width, height, frames, steps}`；音乐 →
  `{caption, lyrics, duration}`；未知 kind / 无参数 → null（不显示按钮）。
  main.js 据此切换 tab 并写入对应表单。

### 2.8 ui:firstRunPane（panes/firstrun.js）【R-ui-09】

- 全屏引导，两条路径二选一：
  1. **选择 models 目录**：文本输入框，预填服务端默认
     （`api:readConfig` 返回的默认 `models_root`）→ `api.completeFirstRun(models_root)`；
  2. **收编既有目录树**：输入 legacy 根路径 → 先给「指向 / 移动」单选
     （文案说明二者含义与移动的空间前提）→ `api.adoptLegacyModels(legacy_root, mode)`。
- 任一调用失败（目录不可写 / 空间不足等）→ 原样展示服务端错误，停留在本页；
  成功 → 重新走启动序列进入台面。
- 目录选择用文本输入即可用；shell 的 `NSOpenPanel`（R-shell-07）如何把选中路径
  灌进输入框是 shell 模块的事，ui 只需要这个输入框存在（见 Assumptions A5）。

### 2.9 ui:settingsPane（panes/settings.js + pure/base_url.js）【R-ui-10】

- 弹层或右侧滑出页。读 `api:gatewayConfig`（开关/host/port）与 `api:readConfig`。
- 可编辑：`enabled` 开关、`host`、`port` → 保存分两步（gateway 设计的既定流程）：
  `api.writeConfig({gateway: {...}})` 落盘，成功后 POST `api:gatewayConfig` 让 gateway
  重读配置并起/停/换绑，用返回的 `data:gatewayStatus` 刷新显示（`listening` 是实测值，
  `last_error` 原样展示——绑定失败不伪装成功）；任一步失败原样展示。
- `base_url.js` 纯函数 `baseUrls({host, port}) -> {openai, anthropic, displayHost}`：
  - OpenAI：`http://<displayHost>:<port>/v1`；Anthropic：`http://<displayHost>:<port>`；
  - `host === "0.0.0.0"` 时 `displayHost` 用占位 `<本机局域网地址>` 并附注
    「0.0.0.0 表示监听所有网卡，从其他设备访问请替换为本机局域网 IP」。
- 两条 URL 各带「复制」按钮（`navigator.clipboard.writeText`）。
- 旁边固定显示警示文案：「当前为无鉴权监听：同一网络任何设备都能调用本机模型」
  （对应 Phase 0 已确认的风险声明）。

### 2.10 api.js（前端唯一 HTTP 出口）

- `request(path, opt)` 包装 fetch：非 2xx 时抛 `DeskApiError {status, code, message}`
  （code 取响应 JSON 的机器可读原因字段，message 取人读信息；无 JSON 则用状态行）。
- 每个被消费的 registry `api:*` 一个导出函数（29 个，见 spec 消费清单）；
  `chatStream` 返回 ReadableStream 而非 JSON。
- URL 常量集中在文件顶部一张表（见 Assumptions A1 的暂定映射）。

## 3. 数据流

```
启动:  main.js ── readConfig ──> needs-setup? ──是──> firstRunPane ──complete/adopt──> 重启序列
                                     │否
                                     v
             初始化 panes + statusbar ── 2s tick ──> deskState + memorySnapshot ──> statusbar
                                                     (作业中) jobStatus ──> video/music pane
                                                     (下载中) downloadProgress ──> resources pane

聊天:  chat.js ── chatStream(messages) ──> stream.js 切行 ──> chat_stream.reduceChunk
           └──(流毕)── updateChatSession(messages 含 reasoning)

媒体:  video/music pane ── startVideoJob/startMusicJob ──> 轮询 jobStatus ──> done: serveOutput URL 播放
回填:  library pane ── listHistory 条目 ──> history_fill.fillPlan ──> main.js 切 tab + 写表单
资源:  resources pane ── listCatalog + verifyAllModels + diskUsage ──> model_status.rowView ──> 行渲染
```

前端唯一的「写」出口是 api.js；面板之间不直接互调，跨面板动作（回填切 tab）经 main.js。
store.js 只保存 tick 的最新快照与当前会话 id，供各 pane 订阅；不做任何缓存持久化
（会话与历史的持久化全在 library 模块，前端无 localStorage 依赖）。

## 4. 错误处理

| 情形 | 行为 |
|---|---|
| api.js 非 2xx | 抛 `DeskApiError`，调用方 pane 内联展示 `message`（保留服务端原文），不吞 |
| 聊天被拒（无模型/媒体在跑） | 消息流内联展示原因；不自动加载、不重试 |
| 加载 LLM 失败 | 展示 `api:llmStatus` 带回的原因（含日志尾部），状态回到可再操作 |
| 作业失败 / 退出码 0 无产出 | 按 `data:jobState` 展示 error 与原因，日志保留可查 |
| 下载被拒 / 失败 | 行内展示原因；进度与已下字节保持显示（可续传） |
| 删除未确认 | ui 总是带确认参数；confirm.js 取消则根本不发请求 |
| 轮询失败 | 单次失败保持旧数据；连续 ≥3 次状态条转「服务失联」，恢复后自动复原 |
| 流中途断开 | chat_stream 状态置 error，已收增量保留展示，消息不写回会话为成功 |
| 静态资源路径逃逸 | desk/ui.py resolve 返回 None → 404 |

全线遵守冻结约定：**不发明回退输出、不伪造成功状态**。

## 5. 测试

### 5.1 服务端（pytest，`tests/test_ui_static.py`，快、确定性）

1. 对真实 `desk/static/` 构造 `StaticAssets`，遍历目录内每个文件：
   `resolve()` 命中、Content-Type 符合后缀表；`/` 与 `/index.html` 均命中 index。
2. 路径逃逸用例：`/static/../ui.py`、绝对路径、`%2e%2e` 解码后逃逸 → None。
3. **R-ui-01 断言**：遍历 `desk/**/*.py`，源码统一转小写后不得出现 `<!doctype` / `<html`
   （大小写不敏感，防 `<!DOCTYPE` 变体漏网）。

## 7. Assumptions（模块内部决定，不改边界）

- **A1 · HTTP 路径映射（Phase 1.2 已与各模块设计落定的路径对齐）**：registry 只冻结接口名，
  不冻结 URL。api.js 顶部的映射表为——
  foundation §2.6：`/api/config`（GET/PUT）、`/api/paths`、`/api/first-run`、`/api/adopt`；
  resources §http.py：`/api/resources/catalog`、`/api/resources/status[?refresh=]`、
  `/api/resources/status/<key>`、`/api/resources/download`（GET 进度 / POST 起或续）、
  `/api/resources/download/cancel`（POST）、`/api/resources/delete`（POST）、`/api/resources/disk`；
  arbiter（组装层挂载，与 shell DeskAPI 同拼写）：`/api/state`、`/api/memory`；
  llm routes：`/api/llm/load`、`/api/llm/unload`、`/api/llm/status`、`/api/llm/chat/stream`；
  media：`/api/media/video`、`/api/media/music`、`/api/media/cancel`、
  `/api/media/job?log_from=N&job_id=K`；
  library：`/api/outputs`、`/api/outputs/<name>`、`/api/history?limit=N`、
  `/api/sessions`（GET/POST）与 `/api/sessions/<id>`（PATCH/DELETE）；
  gateway：`/api/gateway/config`（GET/POST）。
  任一模块再改拼写时只改 api.js 这一处。
- **A2 · 内存警告阈值**：`模型声明字节数 ≥ memorySnapshot.available_bytes` 即警告（字段名按 arbiter `data:memorySnapshot` 合同）。
  不加安全余量系数——arbiter（R-arbiter-07）才是权威判断者，ui 侧这层只是「加载前弹窗」
  的触发条件，宁可略敏感。
- **A3 · 轮询节奏**：2s 基础 tick；下载/作业进行中相关端点并入同一 tick，不另起定时器。
- **A4 · 无前端路由/hash**：面板切换纯内存态，刷新回到聊天面板。单窗口 WebView 内无深链诉求。
- **A5 · 首运目录选择用文本输入**：原生目录选择器属 shell（`api:chooseModelsDirectory`）；
  其注入方式（如 JS bridge 写入输入框）由 shell 设计决定，ui 不依赖它也完整可用。
- **A6 · 单一深色主题**：延续现行视觉；不做浅色适配（内嵌 WebView，无系统主题诉求）。
- **A7 · 会话消息含思考字段（Phase 1.2 已对齐 library）**：assistant 消息以
  `{role, content, reasoning}` 形状写入 `api:updateChatSession`（字段名从 library
  `data:chatSession` 合同；library 不校验消息内部结构，但两侧文档用同一个名字），
  回放时思考仍可折叠查看。chat_stream.js 的累加态键名随之为 `reasoning`。
- **A8 · resources/library 面板数据按「进入面板 + 操作后」拉取**，不进 2s tick
  （verifyAllModels 对 339G 目录树可能慢，不能高频打）。面板提供手动「刷新」按钮。
