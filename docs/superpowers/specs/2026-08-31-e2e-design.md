## 1. 架构

### 1.1 定位

e2e 是**第二个组合根**。生产组合根（`desk/__main__.py`，foundation §1.4）用真实现装配台面
服务；e2e 的测试组装根（`api:launchTestHarness`）用**同一批真组件 + 叶子处的假件**装配同一套
服务，并用 headless Chromium（Python Playwright）以真实浏览器走完 README 的用户旅程。

被替换的东西全是真的：`DeskApp` 路由骨架、foundation 的 config/firstrun、resources 的
verify/downloader 状态机、arbiter 的锁与令牌、llm 的 `LlmService` 状态机、media 的
`MediaService`、library 的三个 Store、gateway 的监听器、`desk/static/` 整个前端。
假的只有五个叶子注入点（spec 冻结的注入表）：

| 注入点 | 兄弟模块已定义的 seam | 假实现 |
|---|---|---|
| LLM 后端 | `LlmBackend` 协议（llm 设计 §backend.py） | `FakeLlmBackend`：spawn 即活、health 即真；`chat_stream` 按剧本吐正文/思考增量，**可在增量之间闸停** |
| 媒体执行器 | `Executor` 协议（media 设计 §executor.py） | `FakeMediaExecutor`：按剧本逐行吐进度、在 argv 解析出的 `--output` 路径写一个极小的真 `.mp4`/`.wav`，再按剧本退出 |
| 下载执行器 | `Executor` 协议（resources 设计 §downloader.py） | `FakeDownloadExecutor`：句柄存活受测试控制；「下载进度」由测试向目的树写字节，真 `Downloader` 的目录采样如实读出 |
| HF 清单 | `fetcher` 注入点（resources 设计 §manifest.py） | `FakeFetcher`：按 `api:listCatalog` 条目**动态生成**固定小清单（不复制任何 repo 字符串清单） |
| 数据根/模型根 | `resolve_paths` 显式入参（foundation §2.1） | 全部指向 `tmp_path`；`resources_root` 为 tmp 内自建的 bundle 态假资源树（§2.2） |

另有三个**为确定性与安全而注入**的小件，均走兄弟设计已声明的构造参数：
`FakeMemoryReader`（arbiter `Arbiter(memory=…)`，R-e2e-10 的剧本源）、
`fake_reaper`（arbiter `Arbiter(reaper=…)`——测试进程绝不对任何真实端口跑 lsof/kill）、
`FixedClock`（media 的 stamp clock → 确定性产物文件名；resources 的 `clock` → 取消升级计时）。

### 1.2 进程模型

```
pytest 进程
  ├─ TestHarness：DeskApp 起在 127.0.0.1:0（线程内 serve），gateway 起在 127.0.0.1:<预分配端口>
  │    全部服务对象与假件同进程 —— 测试代码可直接拨动剧本闸门、读假件调用记录
  ├─ Playwright driver（node 子进程）→ headless Chromium（子进程）
  │    浏览器只经 HTTP 访问 http://127.0.0.1:<port>/ —— 它接触不到任何本地权重
  └─ 断言面 = DOM/属性/网络记录（浏览器侧） + tmp 磁盘/假件调用记录（服务侧）
```

服务起在**线程内、临时端口**：不占 8766（真 App 可能在跑）、假件免序列化、
每个测试一个全新 harness + 全新 `tmp_path`，测试间零共享状态。
`LlmService` 的 `port` 参数传一个**从未监听的临时端口**，`DEFAULT_LLM_PORT`(8767) 在
harness 里不出现——即便本机真有 mlx-lm 驻留，测试也碰不到它。

## 2. 组件

### 2.1 `launch_test_harness`（api:launchTestHarness）

```python
def launch_test_harness(
    tmp_path: Path, *,
    configured: bool = True,          # False → 不写 config.json，走首运流程（R-e2e-02）
    model_states: dict[str, str] | None = None,
                                      # catalog key → "present"|"partial"|"missing"
                                      # 缺省：前三个 chat 条目各铺一态 + h3/music3 铺 present
    gateway_enabled: bool = True,
) -> TestHarness
```

`TestHarness`（dataclass，`close()` 支持 with 语义）：

```python
class TestHarness:
    base_url: str                     # http://127.0.0.1:<port>
    data_root: Path                   # tmp 数据根（config.json / sessions/ / history.jsonl / logs/）
    models_root: Path                 # tmp 模型根
    outputs_root: Path                # tmp 成品根
    gateway_port: int                 # 预分配端口（== config 里写的值，见 §2.5）
    chat: ChatScript                  # 聊天增量剧本 + 闸门
    media: MediaScript                # 媒体作业剧本 + 闸门
    download: DownloadControl         # 下载推进/完成/句柄退出控制 + spawn 记录
    memory: MemoryScript              # 内存快照剧本
    seeded: dict[str, str]            # 实际铺设的 key → 状态（含算好的 partial 百分比）
    def close(self) -> None          # server.shutdown() + 线程 join + gateway.stop()
```

装配步骤（全部走兄弟设计**已定义**的构造 seam，不改任何兄弟接口）：

1. `seed.build_bundle_resources(tmp_path)`：造 bundle 态假资源树（§2.2），
   `seed.seed_models(models_root, catalog, model_states)` 铺三态模型树（§2.3）。
2. `configured=True` 时经 foundation 的 `write_config`/`complete_first_run` 落一份
   `config.json`（`models_root`/`outputs_root` 指 tmp，`gateway` 段指
   `{enabled, host:"127.0.0.1", port:<预分配>}`）；`configured=False` 则不落盘。
3. `roots = functools.partial(foundation.resolve_paths, data_root=…, resources_root=…)`
   —— 唯一的路径入口，逐个注入下述服务。
4. 真组件装配：
   - `Arbiter(llm_port=<临时端口>, memory=FakeMemoryReader(memory_script), reaper=fake_reaper)`；
   - `LlmService(backend=FakeLlmBackend(chat_script), arbiter=…, catalog=…, paths=roots,
     port=<同一临时端口>, load_timeout_s=5, poll_interval_s=0.02)`；
   - `MediaService(executor=FakeMediaExecutor(media_script), clock=FixedClock(...), …)`；
   - `ResourcesService(resolve_paths=roots, can_start_heavy=arbiter.can_start_heavy,
     fetcher=FakeFetcher(catalog), executor=FakeDownloadExecutor(download_ctl))`，
     `Downloader` 的 `sample_interval` 注入 0.05s；
   - `LibraryService(roots)`、`StaticAssets(roots().static_dir)`；
   - `GatewayService(backend=<与生产同款的 GatewayBackend 适配>, read_config=…)`。
5. `DeskApp("127.0.0.1", 0)` + 各模块 `add_routes`（与 `__main__` 同一批路由表：
   foundation routes、`/api/llm/*`、`/api/media/*`、`/api/resources/*`、
   `/api/outputs|history|sessions`、`/api/state`、`/api/memory`、`/api/gateway/config`、静态供给），
   守护线程 `serve_forever`；`gateway_enabled` 时 `start_from_config()`。
6. 把 `LlmService` 的收敛回调订阅到 `arbiter.subscribe`（生产组装同款，llm 设计「让位协作」）。

### 2.2 bundle 态假资源树（能力探测确定性的关键）

media 启动前查 foundation `probe_capabilities` 的 `mlx_h3`/`music_runtime`；dev 态判定
（可执行存在 / 可 import mlx 管线）在测试机不可控。harness 因此统一走 **bundle 态**判定
（纯目录存在性，foundation §2.4）：

```
<tmp>/res/
  bundle.json                        # {"app":"LocalModelDesk","bundle_version":"e2e", ...}
  desk/                              # 仓库 desk/ 的拷贝？不 —— 只拷 static（见下）
    static/                          # shutil.copytree(仓库 desk/static) —— 前端是真的
  python/bin/python3.13              # 指向 sys.executable 的 symlink（capabilities "venv" 判存在+可执行）
  pylibs/desk/  pylibs/h3/mlx_h3/  pylibs/music/mlx_minimax_music3/   # 空包目录，仅供探测判 present
```

`resolve_paths(resources_root=<tmp>/res)` → `mode="bundle"`、`static_dir=<tmp>/res/desk/static`、
五项能力全 present。**拷贝而非 symlink** static，避免 `StaticAssets` 的 resolve 前缀校验
对链接语义敏感；拷贝几十 KB，每测一次可忽略。假解释器 / 空 pylibs 永远不会被执行——
子进程只会经 Fake 执行器「启动」。

### 2.3 三态模型树与假清单（R-e2e-05 的百分比可精确断言）

`FakeFetcher` 对每个 catalog 条目生成同构小清单（文件名取固定模式，**不含**任何真 repo
文件名或第二份目录数据）：`weights/a.safetensors` 600 字节 + `weights/b.safetensors` 400 字节。
`seed_models` 据此铺树：

| 状态 | 铺法 | 期望渲染 |
|---|---|---|
| present | 两文件足量字节 | 徽标「齐」，percent 100 |
| partial | a 足量、b 缺失 | 徽标「一半 60%」（600/1000，按字节，精确可断言） |
| missing | 目录不存在 | 徽标「没下」 |

h3 / music3 条目默认铺 present（媒体流程不做完整度预检，media 设计 Assumption 10，
但资源面板会显示它们）。清单内容纯由 `FakeFetcher` 供给，manifest 缓存照常落
`<data root>/manifests/`——走的是真 `ManifestStore`。

### 2.4 剧本与闸门（`scripts.py`）

所有假件共用一个原语 `Gate`（`threading.Event` 包装，带 5s 超时抛 `ScriptStall`——
剧本饿死表现为清晰失败，不是挂死）：

- **ChatScript**：步序列，如
  `[Delta(reasoning="让我想想，"), Gate, Delta(reasoning="想好了。"), Gate,
    Delta(content="你好"), Gate, Delta(content="，世界"), Done(usage, "stop")]`。
  `FakeLlmBackend.chat_stream` 逐步产出 mlx-lm 形状的 chunk
  （`{"choices":[{"delta":{"content"|"reasoning_content": …}}]}`，终块带 usage/finish_reason），
  遇 `Gate` 阻塞直到测试调 `harness.chat.step()`。这是 R-e2e-03「增量确实分批到达」的
  证明机制：闸停时浏览器已收到且只收到前面的帧。
- **MediaScript**：`[Line("step 1/10"), Gate, Line("step 5/10"), Gate,
    WriteOutput, Exit(0)]`。`WriteOutput` 把 `seed.TINY_MP4` / `TINY_WAV` 字节写到
  spawn argv 里解析出的 `--output` 路径（顺带证明命令构造把输出路径传对了）。
  剧本可配 `Exit(1)`（失败路径，本模块不用——单测已覆盖）与「阻塞直到 terminate」
  （R-e2e-08 的运行中状态）。
- **DownloadControl**：`spawns: list[argv]` 记录；`advance(key, n_bytes)` 向目的树写字节
  （真 Downloader 的采样线程如实读出进度）；`finish(key)` 补齐全部清单文件并让句柄
  exit 0；`exit_after_terminate()` 控制 cancel 后句柄何时退出。
- **MemoryScript**：`snapshots: deque[MemorySnapshot]`，`FakeMemoryReader.snapshot()`
  取队首（队列只剩一个时重复返回）；`push(snapshot)` 供测试切换读数。

### 2.5 gateway 端口预分配

设置面板显示的 base URL 来自 gateway 配置/状态里的 host:port。为避免「配置写 0、
状态报实端口」两个来源的歧义，harness 先 `bind(("127.0.0.1", 0))` 取一个空闲端口 N、
立即关闭，再把 N 写进 config 的 `gateway.port` 并真监听——配置值与实测值恒等，
R-e2e-11 的断言无二义。host 用 `127.0.0.1`：**e2e 不绑 0.0.0.0**（无鉴权面不进测试机局域网；
0.0.0.0 行为归 gateway 自己的测试与 D-0002 的 LAN 自证，不归本模块）。

### 2.6 conftest 的三道常设护栏（autouse）

1. **越界审计**（R-e2e-01 的行为证明）：session 级 `sys.addaudithook` 记录 `open` 事件中
   路径落在 `<repo>/llms`、`<repo>/minimax-h3`、`<repo>/minimax-music3`、`<repo>/outputs`
   之下的访问；function 级 autouse fixture 在 teardown 断言记录为空。审计钩子装一次、
   永不卸（CPython 限制），记录器按测试清零。仓库内**代码**（desk/、desk/static 拷贝源）
   不在禁区——禁区就是授权红线列出的四个数据目录。
2. **8767 记录器**（R-e2e-12 的全程面）：每个 `context` 挂 `context.on("request")`，
   收集全部请求 URL；teardown 断言无一 URL 含 `:8767`。专项测试（test_no_direct_llm）
   在此之上再做显式的旅程级断言。
3. **pageerror 即失败**：`page.on("pageerror")` 收集未捕获 JS 异常，teardown 非空即 fail
   （前端错误按 ui 设计走内联 DOM 展示，不该有未捕获异常）。

另有失败取证：测试失败时把 `page.content()`、console 消息、`<data root>/logs/desk.log`
尾部落到 `tmp_path/e2e-artifacts/`（pytest hook `pytest_runtest_makereport`），便于人读。

## 3. 数据流

### 3.1 一次典型断言回路（以聊天流式为例）

```
test_chat_stream.py
  h = launch_test_harness(tmp_path)          # 服务线程起，present 模型已铺
  page.goto(h.base_url)                       # ui:deskShell 加载（真前端）
  选模型 → 点「加载」                          # ui → POST /api/llm/load → LlmService(FakeLlmBackend)
  expect(状态区含模型名)                       #   spawn 即活、health 即真 → loaded（毫秒级）
  输入消息 → 发送                              # ui → POST /api/llm/chat/stream（SSE）
  expect(思考块出现且含"让我想想")              # FakeLlmBackend 已吐第 1 步，闸停中
  len1 = 正文长度;  h.chat.step()             # 放行一步
  expect(正文长度 > len1)                      # ← 增量分批到达的直接证据
  … 逐闸推进到 Done …
  expect(思考 <details> 可展开、正文完整)
  断言 h.data_root/sessions/<id>.json 含 assistant 消息 {content, reasoning}   # 回复入库
```

服务侧一切都是真的：SSE 帧由 llm routes 编码、会话由 library 落盘、
状态条数字来自 arbiter（FakeMemoryReader 的注入值）。

### 3.2 控制面与观察面

```
测试线程 ──(直接方法调用)──> scripts.* 闸门/推进 ──> 假件 ──> 真服务状态演进
测试线程 <──(Playwright expect/DOM/网络记录)── Chromium <──HTTP── DeskApp(真路由/真前端)
测试线程 <──(直接读 tmp 磁盘/假件记录)── config.json / sessions/ / history.jsonl / outputs/ / spawns
```

双面观察是反同义反复的结构保证：每条旅程既断言 DOM 呈现，又断言持久化/调用记录的
服务侧事实，二者必须同时成立。

## 4. 错误处理

| 情形 | 行为 |
|---|---|
| harness 装配/绑定失败 | `launch_test_harness` 抛异常，pytest error（非 fail），附 desk.log 尾部 |
| 剧本饿死（无人放行 Gate） | 5s 后 `ScriptStall` → SSE/作业侧如实收错，测试以清晰断言失败收场，不挂死 |
| 剧本步序耗尽仍被拉取 | 假件抛 `ScriptExhausted`（编程错误即错误，不静默补帧） |
| 页面未捕获 JS 异常 | autouse 护栏 teardown fail（§2.6-3） |
| 任何对 `:8767` 的浏览器请求 | autouse 护栏 teardown fail（§2.6-2） |
| 任何对真权重/真 outputs 的 open | autouse 护栏 teardown fail（§2.6-1） |
| Playwright 等待超时 | 默认 expect 超时 10s（UI tick 2s 的 5 倍），失败取证落盘 |
| teardown | `close()` 幂等：关 context → server.shutdown → gateway.stop → 线程 join(5s)，join 失败报 error |

harness 自身不吞任何服务端错误：服务返回什么，浏览器就渲染什么，测试就断言什么——
e2e 不给被测系统递台阶（冻结约定：错误保持错误）。

## 5. 测试（12 个验收文件 = 12 条需求）

每文件独立可跑：`python3 -m pytest tests/e2e/test_<flow>.py`。全部 headless、tmp_path、
假后端，**零 reality gate**。预算：单文件 < 60s，全套 < 6min（UI tick 2s 是主要等待项）。

| 文件 | 需求 | 关键断言（非同义反复的部分） |
|---|---|---|

## 6. Assumptions（模块内部决定，未越出边界）

- **A1 · harness 落在 `desk/testing/`**：`api:launchTestHarness` 是注册表接口，可能被
  packaging 的验证步消费，故做成可 import 的包内模块而非 tests/ 下的散件。它是
  「第二组合根」，与 `desk/__main__.py` 平行；只 import 兄弟模块的**已设计公开面**
  （服务类构造参数、路由表、协议类型），不 reach 进任何内部函数。体积数 KB，
  随包分发无害。
- **A2 · 只用兄弟设计已声明的注入 seam**：`LlmBackend`、media/resources 的 `Executor`、
  `fetcher`、`resolve_paths` 显式入参、`Arbiter(memory=…, reaper=…, clock=…)`、
  `LlmService(port=…, load_timeout_s=…, poll_interval_s=…)`、`Downloader(sample_interval=…)`、
  media 的注入 clock。D-0001 的指令即「build on the seams they already define」；
  实现期若某 seam 拼写有出入，改动收敛在 `harness.py` 装配处。
- **A3 · bundle 态假资源树**（§2.2）而非 dev 态：能力探测（`mlx_h3`/`music_runtime`）在
  bundle 态是纯目录存在性判定，测试机上确定；dev 态依赖「mlx 管线可 import」不可控。
  顺带让 e2e 全程走安装态路径判定，多证明一层。static 用拷贝不用 symlink。
- **A4 · 服务起在线程内、临时端口**，不占 8766/8770/8767；`llm_port` 传临时值且 reaper
  是假件——e2e 进程对真实端口零操作。这同时满足「不碰真机 mlx-lm」与并行跑测试不互踩。
- **A5 · 不改 ui 的 2s tick**：等待用 Playwright 自动等待（expect 超时 10s）吸收，
  不为测试给前端开后门参数。代价是全套多花约 1-2 分钟，换来「被测前端与生产逐字节相同」。
- **A6 · R-e2e-10 的「真实内存数值」在测试态解释为「来自注入 MemorySnapshot 的数值」**：
  断言数字随注入快照变化且无 128 字面量——这证明的是 UI→`api:memorySnapshot` 的数据通路
  无写死值；「读数本身来自 sysctl」由 arbiter 的真机单测（其 test_arbiter_memory）承担，
  e2e 不重复也不需要真读数（真读数反而不确定）。
- **A7 · 播放断言止于 `src` + HTTP 可取**：TINY_MP4/TINY_WAV 是极小但头部合法的真文件；
  「解码后可播」属编解码器行为，无法在 headless 断言且不属被测代码。spec 原文即
  「播放器出现且 src 指向新成品」。
- **A8 · 越界审计用 `sys.addaudithook` 的 open 事件**：覆盖 pytest 进程内一切 Python 文件
  访问；Chromium 子进程只有 HTTP 面，物理上无从触碰权重。禁区 = 授权红线的四个真实
  数据目录，仓库代码目录不设禁（服务要读 desk/static 拷贝源与 .py）。
- **A9 · FakeFetcher 的清单文件名用固定模式（`weights/a.safetensors` 等）**，不复制任何
  真实 repo 的文件清单；假件全部元数据派生自 `api:listCatalog` 运行时返回——resources
  的 census 守卫（hf_repo 字符串全仓唯一）对 `desk/testing/` 同样成立。
- **A10 · gateway 在 harness 里绑 127.0.0.1 + 预分配端口**（§2.5）：不把无鉴权面暴露进
  局域网；0.0.0.0 与 LAN 路径的验证归 gateway 模块（D-0002）。
- **A11 · 依赖安装**：`playwright==1.62.0` 与 `pytest` 装进跑验收的环境属实现任务的
  一次性 setup（一条 pip 命令）；测试运行期零下载（浏览器已缓存）。conftest 在
  playwright 缺失时给出明确 error 信息（不是 skip——验收依赖缺失是错误，不是可跳过项）。
