# 模块 spec：llm

**单一职责** 聊天模型的加载、卸载、健康与流式对话。所有重活许可向 `arbiter` 申请，自己不做互斥判断。

## 背景约束

现状浏览器直接 POST 到 `127.0.0.1:8767`，绕过服务端自己的 `/api/llm/chat/stream` 代理——
该代理有测试、却是死代码。本模块之后，**前端一律不得直连 mlx-lm 端口**：
mlx-lm 的端口是实现细节，会随每次卸载消失。

## 需求

- **R-llm-01** 按目录 key 加载聊天模型：先向 `arbiter` 申请许可，再启动 mlx-lm 服务，
  轮询健康直到就绪。状态可查：`idle` / `loading` / `loaded` / `error`。
- **R-llm-02** 卸载当前模型，并确认 LLM 端口确已释放（走 `api:reapLlmPort`，不只是终止自己的子进程）。
- **R-llm-03** 流式对话：逐 token 输出正文增量，并把思考/推理增量（`reasoning_content` / `reasoning`）
  作为独立字段与正文分开传给上层，不混在一起。
- **R-llm-04** 加载失败必须给出原因（mlx-lm 日志尾部），不得只报一个「加载超时」。
- **R-llm-05** 报出当前加载的是哪个模型及其元数据（视觉能力、量化、参数量、体积）。
- **R-llm-06** 媒体作业进行中、或当前没有加载模型时，聊天请求被拒绝并带明确原因，不得挂起等待。
- **R-llm-07** 对话必须经由本服务转发；前端与外部客户端都不直连 mlx-lm 端口。

## 暴露

`api:loadLlm`、`api:unloadLlm`、`api:llmStatus`、`api:chatStream`、`api:chatCompletion`、
`data:llmState`、`data:loadedModel`

## 消费

`api:acquireHeavy`、`api:releaseHeavy`、`api:reapLlmPort`、`api:canStartHeavy`、`data:deskState`、
`api:listCatalog`、`data:modelEntry`、`api:resolvePaths`

## 验收取向

mlx-lm 进程的启动与 HTTP 调用都走可替换的后端接口，单元测试注入假后端：
假后端可以模拟「启动即退出」「一直不就绪」「正常流式」「返回 reasoning 增量」四种情形，
分别断言 R-llm-01/03/04 的行为。
「加载一个真实模型并真的收到 token」标 `reality_gate`——要占十几到几十 GB 内存且耗时。
