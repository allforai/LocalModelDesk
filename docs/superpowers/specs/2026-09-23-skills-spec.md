# 模块 spec：skills（指令包）

**单一职责** 把一段人写的指令，可预期地、可见地放进模型的上下文——不执行任何东西。

## 背景约束

台面今天没有任何「改变模型行为」的手段：每个会话都是裸模型加聊天记录。

用户要的是 Claude Code 那样的 skill。这一摊其实是三件分量差很多的东西：工具调用的骨架、
具体的工具（websearch 等）、以及 skill 指令包。前两件是一个子系统（模型发起调用 → 有人执行
→ 结果回流），第三件不依赖它们。**本 spec 只做第三件**，并把边界钉死：skill 不执行任何东西。

三个实地核对过的事实约束了设计（2026-09-23，核对 `~/.claude/plugins/cache/` 与
`~/.pi/agent/skills/`）：

1. **格式是现成的，且不用选边。** Claude Code 与 Pi 的 skill 用的是同一个格式：一个目录，
   里面一份 `SKILL.md`，YAML 头带 `name` 与 `description`，正文是 markdown。兼容这一个格式
   即同时兼容两个生态。

2. **生态的内容基本不适用。** 那些 skill 是写给**会用工具的 agent** 的，正文里是「派一个
   子 agent」「跑这个脚本」「读 references/xx.md」。台面上是纯聊天模型：没有工具、不能执行、
   打不开别的文件。装进去它会照着念一套自己做不到的流程。**格式可抄，内容不可抄**——所以
   自带与自建是主路径，从外部装是补充。

3. **一个 skill 往往是一个目录，`SKILL.md` 只是索引。** 正文散在旁边的 `.md` 里（如 Pi 的
   `codebase-design/` 下有 `DEEPENING.md`、`DESIGN-IT-TWICE.md`），靠 markdown 链接串着。
   工具型 agent 读到链接会去打开；聊天模型只会看到一个它够不着的文件名。

本项目尚未发布，不存在需要兼容的存量行为。

## 需求

- **R-skill-01** skill 是**指令，不是能力**。台面不执行 skill 里的任何东西：不跑脚本、
  不发请求、不自动跟随它写的链接。skill 唯一的作用是把文字放进上下文。

  「不自动跟随」与 R-skill-10 不矛盾：那里是用户明确勾选了某份附件，台面照原文拼进去。
  区别在于谁做的决定——台面从不替模型去取它指名的东西。

  这条是边界，不是限制。工具调用是另一个子系统，它需要模型能发起调用、有人执行、结果能
  回流——三样这里都没有。把两者混在一起，会得到一个「看起来会干活、其实只会念稿」的东西。

- **R-skill-02** **进模型的每个字都是原文，台面不转述。**

  `SKILL.md` 全文注入；附件要么由用户勾选后原文拼进去，要么根本不进去。**不做模型摘要。**

  理由：整个设计里别处出错都看得见——文件坏了界面会说，token 超了界面会显示。唯独摘要
  错了没人知道：模型漏掉一条规则，skill 就变成另一个意思，而用户看到的是「已摘要 ✓」。
  而这套机制大部分时间在空转（自建的 skill 通常只有一份 `SKILL.md`，附件是外部生态的产物，
  而那些附件恰恰是最不适用于聊天模型的那部分）。为一个常在空转的功能引进设计中唯一一处
  静默失真，不划算。

- **R-skill-03** **选中由用户完成，不由模型判断。**

  输入框上方的芯片：点一下开，再点一下关，作用于整个会话。

  模型自选（Claude Code 的做法）不做：本地模型在这一步很不稳，挑错了用户发现不了，而且
  每轮都要为所有描述烧 token。`description` 字段仍然读取、保存、显示——以后若要改成模型
  自选，选择逻辑换掉即可，数据模型不必推倒重来。

- **R-skill-04** 可同时开多个，按选中顺序拼接。

- **R-skill-05** skill 的文字作为 `system` 消息排在最前，**永不参与压缩**。

  实现上天然如此：它不存进 `session.messages`，而是每次发送时由 `wireMessages` 现拼。
  摘要替换（`replaced_through`）因此碰不到它，它也不占会话存档。

  一个后果必须在界面上说明：**改了 `SKILL.md`，老会话的下一轮就用新版本**，不会继续用
  当时那一版。skill 是「当前的指令」，不是「当时说过的话」。

- **R-skill-06** **skill 的 token 占用必须可见。**

  芯片上写明这个 skill 占多少 token；选中后在输入框上方显示「skill 占用 X / 额度 Y」，
  额度取自驻留模型的 `budget.for_chat(...).token_limit`。

  没有加载模型时没有额度可比：只显示占用量，不显示分母，也不发警告——**不拿一个猜的
  分母顶替**（与 R-budget-16 同一条纪律）。

  **token 数本身也可能量不出来。** 前端没有 tokenizer，每 token 字符数只能从上一轮真实
  请求反推（`charsPerToken`）。这个模型还没聊过就没有比值：此时只显示字符数并标明
  「还没量过」，**不套默认比值**——`compaction.js` 的模块注释已经定了这条房规
  （「量不到就返回 null……而不是套一个默认值」），这里沿用。

  警告出现在选中的那一刻，不是发送时：用户改变选择时就该看到代价。

  占比超过额度的 30% 时**警告而不禁止**——是用户的机器，由他决定。

  资源管理是这个产品的核心承诺（见 `2026-09-17-budget-spec.md`）。skill 吃掉窗口却不显示，
  等于在这个承诺上开一个洞。

- **R-skill-07** 两个来源，用户的覆盖自带的。

  - 自带：app 包内 `resources_root/skills/`，只读，升级时整体替换。
  - 用户：`<models_root>/skills/`，与 `llms/` 并排。用户已经认识这个文件夹（首次设置里
    选的就是它），不为 skill 另立一个新根。从外部装进来的也落在这里。

  同名时用户的生效，界面标明「已覆盖自带的同名 skill」——覆盖必须看得见。

- **R-skill-08** **坏的 skill 照样列出来，并写明坏在哪。**

  缺 `name`、缺 `description`、YAML 解析不了、目录里没有 `SKILL.md`——一律列出并给出原因，
  不得静默跳过。悄悄消失是最难查的故障。

  坏的 skill **不可被选中**：芯片置灰，原因写在旁边。列出来是为了让人能修，不是为了能用。

- **R-skill-09** 发现是显式的：启动时扫一次，外加一个「重新扫描」按钮。

  不做文件监听：多一个后台线程与一类时序故障，收益不抵复杂度。用户在外部编辑器改完文件，
  点一下重新扫描即可。

- **R-skill-10** 附件不隐身。

  「引用了哪些文件」的判据写死：扫 `SKILL.md` 里的 markdown 链接，取其中指向**同目录下
  `.md` 文件**的那些。目录外的路径、URL、非 `.md` 一律不算——台面不跟出这个目录。

  界面列出这些文件、标明哪些没有放进上下文，每个旁边一个勾选框；勾中的原文拼接进去，
  并计入 R-skill-06 的 token 显示。

  「没放进去」这件事必须写在明处。R-skill-02 用完整性换掉了失真，代价就落在这里——
  代价要看得见，才算是用户做的选择。

- **R-skill-11** 从外部装：先看全文，再落盘，装完不启用。

  贴仓库 URL → 下载到暂存目录 → 把 `SKILL.md` **全文**摆给用户 → 用户确认后才落进
  `<models_root>/skills/`。

  - **装完默认不启用。** 装和用是两个动作。
  - 只落 `SKILL.md` 与 `.md` 附件；脚本、二进制一律不落盘——台面不执行它们（R-skill-01），
    留着只会让人以为它会执行。

  这是台面第一次让外部文本进入模型的上下文。skill 就是指令，装一个别人写的 skill 等于让
  别人写的指令驱动你的模型——「先看全文」这道不能省。

## 闭环需求

以下六条来自对上面十一条的闭环自审（2026-09-23）：每条产生的东西有没有人读、每个
问题是不是只有一个入口、每条路径的失败出口在哪。前两条是真漏，不是措辞问题。

- **R-skill-12** **压缩的预算必须扣掉 skill 的占用。**

  `splitForCompaction` 今天算的尾部预算是 `compactAt × TAIL_FRACTION × ratio`，意思是
  「历史原文最多留多少」。skill 占着同一个窗口，却不在 `messages` 里——不扣掉它，压完
  仍然超，于是下一轮再压。大 skill 下这会收敛不了，表现为反复摘要、历史越摘越短而总量
  不降。

  这是「前提变了（窗口里多了一块常驻文字），建在它上面的算账没跟着变」的又一个实例。
  `splitForCompaction` 必须收下 skill 的占用并从预算里扣除。

- **R-skill-13** **skill 必须落在 `sentChars` 的度量范围之内。**

  每 token 字符数由 `ratio = sentChars / promptTokens` 反推。skill 必然计入上游返回的
  `promptTokens`；若它没有计入 `sentChars`，比值偏小，之后所有由它换算的字符预算跟着
  偏小——而且没有任何迹象。

  所以 skill 必须由 `wireMessages` 拼进去（在 `chat.js` 测量 `sentChars` 之前），不得在
  更下游的任何一层追加。

- **R-skill-14** 选中集合与可用集合必须对账。

  用户可能在文件夹里删掉或改坏一个正被选中的 skill。每次扫描后，选中集合与可用集合求交；
  消失或变坏的在界面上明说「已不存在 / 已损坏，已取消选中」，**不得静默丢弃，也不得继续
  注入一份已经不在的文件**。

- **R-skill-15** 选中状态（含附件勾选）是**会话级**的，随会话存档。

  附件勾选不写回 skill 目录——自带目录是只读的（R-skill-07），写回会在那里破功；而且
  同一个 skill 在不同会话里想带的附件本就可以不同。

- **R-skill-16** 扫描产出**唯一一份已解析列表**，注入只读它。

  来源优先级、同名覆盖、坏文件判定全部在扫描那一步定完，产出一份扁平列表。注入、计数、
  界面显示都只读这份列表，**不得再判定一次**。

  今天已经在别处付过这个代价：同一个问题有两个入口时，答案迟早分叉，而先被问到的那个
  说了算（见 `2026-09-17-budget-spec.md` 的 R-budget-18）。

- **R-skill-17** 安装**全部成功才落盘**，任何中断清掉暂存。

  下载失败、用户确认前退出、落盘中途失败——一律清掉暂存目录，不留半成品。
  `<models_root>/skills/` 下不允许出现「装了一半」的目录：它会被扫描发现、被 R-skill-08
  列成坏 skill，而用户根本没同意装它。

## 不在本 spec 范围内

- 工具调用骨架与 websearch：另一个子系统，另开 spec。
- 模型自选 skill：数据模型已留好 `description`，但本次不实现（R-skill-03）。
- 台面内建的 skill 编辑器：用户在自己的编辑器里写（R-skill-07、R-skill-09）。
- 附件的模型摘要：明确不做（R-skill-02）。
- 文件监听：明确不做（R-skill-09）。
